# راهنمای اجرا و جمع‌آوری داده — MIR Parity Lab

نسخه فاز ۱، ابزار آفلاین. این راهنما برای اپراتور پژوهشی است، نه برای تصمیم بالینی.

## ۱. پیش از اجرا

- ویندوز ۷/۸/۱۰/۱۱ با .NET Framework 4.x.
- برنامه portable است؛ نیازی به نصب، ادمین یا درایور MIR ندارد.
- اینترنت لازم نیست. ابزار هیچ اتصال شبکه‌ای باز نمی‌کند.
- همه فایل‌ها را در یک پوشه محلی نگه دارید. از مسیرهای شبکه‌ای استفاده نکنید.
- هیچ داده هویتی بیمار وارد نکنید. فقط `test_id` غیرهویتی.

## ۲. اجرا

```bat
cd mir-parity-lab
run.bat
```

یا:

```bat
release\MIRParityLab.exe
```

اگر برنامه باز نشد:

1. وجود `.NET Framework 4.x` را بررسی کنید.
2. `build.bat` را اجرا کنید و خطای کامپایل را ببینید.
3. مطمئن شوید `ParityLab.Core.dll` کنار `MIRParityLab.exe` است.
4. برنامه را از `release` اجرا کنید، نه از ریشه پروژه.

## ۳. تب Capture

- `Load capture...`: فایل JSON بومی، لاگ دستگاه، hex یا blob را باز می‌کند.
- `Load synthetic demo`: فقط برای آزمایش رابط و قرارداد داده است. برچسب **SYNTHETIC** روی سربرگ ظاهر می‌شود.
- `Packets`: زمان، نوع، مقدار خام، طول، hex و توضیح.
- `Decoded fields`: آفست، اندازه، خام، u16، مقدار، واحد، تبدیل، اصالت و شاهد.
- `Unknown bytes`: بازه‌های بایت‌ناشناخته با hex کامل؛ هیچ تفسیری ندارد.
- فایل‌های `.mir` به‌صورت آرشیو opaque بارگذاری می‌شوند. اگر ابزار بگوید «آرشیو است، نه داده خام USB»، این پیام درست است. آن را به‌عنوان capture خام برچسب نزنید.

## ۴. تب Official MIR evidence

دو راه ورود:

1. `Load official CSV...`
2. `Add manual value...`

برای هر ردیف:

- `test_id` باید با capture یکی باشد.
- `maneuver_key` را دقیقاً از برگه جفت‌سازی کپی کنید.
- `parameter` را از فهرست استاندارد انتخاب کنید: `FVC`, `FEV1`, `PEF`, `FET`, `PEF_TIME`, `FEV1/FVC`, `FEF25-75`, `FVC_PRED`, `FEV1_PRED`, `PEF_PRED`.
- `value` را با همان دقت نمایش رسمی وارد کنید.
- `unit` را دقیق وارد کنید: `L`, `mL`, `L/s`, `mL/s`, `L/min`, `s`, `ms`, `%`.
- `source` را دقیق انتخاب کنید. خروجی نرم‌افزار SpiroLab را هرگز `mir_device_display` یا `mir_device_print` نگذارید.
- `precision` را از خود خروجی رسمی بردارید؛ مثلاً `0.01` برای دو رقم اعشار.
- `same_maneuver_attested` فقط وقتی `yes` باشد که اپراتور واقعاً همان مانور را جفت کرده باشد.
- `evidence` را کوتاه و قابل‌ردیابی بنویسید؛ مسیر فایل یا کد ردیف، نه داده هویتی.

قالب را می‌توانید با `Save CSV template` ذخیره کنید.

## ۵. تب Comparison

ستون‌ها:

- `Official` و `Official source`: مقدار و منبع رسمی.
- `Decoded`: مقدار مستقیم `cod_LAST`؛ اگر فیلد مستقیم نباشد خالی است.
- `Decoded provenance`: اصالت مقدار خوانده‌شده.
- `Software`: بازسازی مستقل Parity Lab.
- `SpiroLab`: مقدار نرم‌افزاری SpiroLab، اگر جداگانه وارد شده باشد.
- `Abs diff` / `Rel diff %`: اختلاف مقدار رسمی با مقدار خوانده‌شده.
- `Tolerance`: فقط پوشش گردکردن.
- `Status`: وضعیت عددی.
- `Same maneuver`: آیا شاهد کافی برای همان مانور وجود دارد.
- `Reason`: دلیل وضعیت.

### معنی وضعیت‌ها

| وضعیت | معنی |
|---|---|
| `within_rounding_tolerance` | اختلاف در پوشش گردکردن است؛ نه اثبات برابری |
| `outside_rounding_tolerance` | اختلاف بیش از پوشش گردکردن است؛ علت نامعلوم |
| `identity_not_established` | شاهد کافی برای همان مانور نیست |
| `no_mir_reference` | فقط مقدار SpiroLab/نرم‌افزاری، بدون مقدار رسمی |
| `no_captured_value` | فیلد مستقیم دستگاه برای این پارامتر وجود ندارد |
| `tolerance_not_established` | دقت رسمی وارد نشده است |

`software_status` در CSV/JSON جداگانه ثبت می‌شود. مقدار نرم‌افزاری حتی اگر نزدیک باشد، `Device-reported` نیست.

## ۶. خروجی

- `Export CSV`: جدول کامل، مناسب تحلیل.
- `Export JSON`: ساختار کامل capture، فیلدها، بازه‌های ناشناخته، مقایسه و محدودیت‌ها.
- `Export report`: گزارش Markdown فارسی با هشدار روش‌شناختی.

نام فایل‌ها را با `test_id` و تاریخ غیرهویتی بسازید. مسیر کامل فایل مبدأ در خروجی ذخیره نمی‌شود؛ فقط نام پایه و SHA-256.

## ۷. جمع‌آوری داده واقعی (فاز ۲)

1. دستگاه را با کابل USB مستقیم، بدون هاب، به یک رایانه اختصاصی وصل کنید.
2. همه نرم‌افزارهای MIR/SpiroLab را ببندید تا دسترسی انحصاری باشد.
3. مدل، شماره سریال دستگاه، نسخه firmware، نسخه winspiroPRO/MIR Spiro، نسخه SpiroLab و نسخه ویندوز را ثبت کنید.
4. یک `test_id` غیرهویتی بسازید.
5. برای هر مانور، ترتیب، PRE/POST، زمان محلی و UTC، و شرایط آزمون را ثبت کنید.
6. خروجی نمایشگر، پرینت و نرم‌افزار رسمی همان مانور را جداگانه ذخیره کنید.
7. لاگ خام USB و `cod_LAST`/`cod_CURVE` را فقط با ابزار اثبات‌شده و در دسترسی انحصاری تهیه کنید.
8. هیچ فرمان ناشناخته، تنظیمات، کالیبراسیون، حافظه، رکورد، سریال، ارتباط یا زمان را تغییر ندهید.
9. بسته شواهد را با چک‌لیست `docs/data-collection-checklist.md` تطبیق دهید.
10. اگر وضوح کافی برای جفت‌سازی همان مانور ندارید، مقایسه عددی را متوقف کنید.

## ۸. خطاهای رایج

| پیام | اقدام |
|---|---|
| `PrivacyException` | کلید شناسایی بیمار را حذف کنید؛ `test_id` غیرهویتی بگذارید |
| `CSV ... missing required column` | ستون‌های الزامی را کامل کنید |
| `unit ... dimension mismatch` | واحد را با پارامتر هم‌بعد کنید |
| `block below observed minimum` | بلوک ناقص است؛ عدد را معتبر ندانید |
| `stale_duplicate` | بلوک تکراری است؛ به‌عنوان مانور جدید استفاده نکنید |
| `association ... not capture-bound` | شاهد انتساب کافی نیست؛ مقدار Unverified است |
| `opaque archive` | فایل `.mir` داده خام USB نیست؛ رمزگشایی نکنید |

## ۹. مرزهای مجاز

- بله: خواندن فایل، محاسبه، مقایسه، گزارش.
- خیر: ارسال فرمان USB، نوشتن روی دستگاه، کالیبراسیون، تغییر firmware، تغییر حافظه، ارسال HLine، اتصال شبکه.
- خیر: استفاده از بایت ناشناخته برای تصمیم بالینی.
- خیر: برچسب `Device-reported` روی مقدار محاسبه‌شده.
