# چک‌لیست جمع‌آوری داده برای فاز ۲

هدف: ساختن بسته شواهدی که بتواند یک مانور واحد را بین نمایشگر دستگاه، پرینت، نرم‌افزار رسمی MIR، بسته USB و مقدار SpiroLab جفت کند — بدون داده هویتی.

> تا زمانی که این چک‌لیست کامل نشده، هیچ مقایسه عددی به‌عنوان «همان مانور» ارائه نکنید.

## ۰. اصل ایمنی

- [ ] هیچ فرمان ناشناخته ارسال نمی‌شود.
- [ ] هیچ تغییر firmware/calibration/settings/memory/record/serial/communication/time انجام نمی‌شود.
- [ ] هیچ نوشتن/پاک‌کردن/به‌روزرسانی روی دستگاه انجام نمی‌شود.
- [ ] دسترسی USB انحصاری است؛ SpiroLab، winspiroPRO، MIR Spiro و هر ابزار دیگر هم‌زمان باز نیستند.
- [ ] اگر برای خواندن آرشیو به فرمان اثبات‌نشده نیاز شد، کار متوقف و به آزمون مستقل/مستندات ارجاع می‌شود.
- [ ] هیچ داده‌ای به HLine یا شبکه ارسال نمی‌شود.

## ۱. شناسایی محیط

- [ ] مدل دقیق دستگاه: `Spirolab` / `Spirolab Plus` / ... .
- [ ] شماره سریال دستگاه (غیرهویتی؛ در گزارش فقط در صورت نیاز).
- [ ] نسخه firmware (از منوی دستگاه/About).
- [ ] نسخه سخت‌افزار/توربین: reusable یا FlowMIR disposable.
- [ ] شماره سریال توربین در صورت وجود.
- [ ] تاریخ آخرین کالیبراسیون و روش آن.
- [ ] نسخه ویندوز و build.
- [ ] نسخه درایور `MIRUSB.SYS`.
- [ ] نسخه SpiroLab و commit (اگر از سورس اجرا می‌شود).
- [ ] نسخه MIR Spiro / winspiroPRO.
- [ ] نسخه SDK و .NET Runtime (اگر استفاده شد).
- [ ] پورت USB مستقیم، بدون هاب؛ کابل اصلی.
- [ ] تنظیمات منطقه/زبان/واحد دستگاه ثبت شود.

## ۲. آزمون و مانور

- [ ] `test_id` غیرهویتی ساخته شد؛ مثلاً `LAB-2026-11-A`.
- [ ] هیچ نام، تاریخ تولد، MRN، شماره ملی، آدرس، تلفن یا ایمیل در فایل نیست.
- [ ] شرایط آزمون ثبت شد: seated/standing، nose clip، mouthpiece/filter، آموزش، تلاش‌ها.
- [ ] ترتیب مانورها از پیش تعیین شد.
- [ ] PRE/POST و زمان برونکودیلاتور ثبت شد.
- [ ] برای هر مانور `maneuver_key` یکتا ساخته شد؛ مثلاً `LAB-2026-11-A-M1`.
- [ ] زمان محلی و UTC ثبت شد.
- [ ] حداقل سه مانور قابل‌قبول یا برچسب «غیرقابل‌قبول» ثبت شد.
- [ ] هیچ تلاش ناموفق حذف نشد؛ وضعیت آن ثبت شد.

## ۳. خروجی نمایشگر دستگاه

- [ ] صفحه نتیجه همان مانور عکس/اسکرین‌شات گرفته شد.
- [ ] `FVC`, `FEV1`, `PEF`, `FET`, `PEF time` و هر پارامتر نمایش‌داده‌شده ثبت شد.
- [ ] دقت نمایش هر عدد (تعداد اعشار) ثبت شد.
- [ ] واحد هر عدد ثبت شد.
- [ ] شماره مانور/ترتیب روی صفحه ثبت شد.
- [ ] ساعت دستگاه و ساعت رایانه هم‌زمان ثبت شد.

## ۴. پرینت دستگاه

- [ ] پرینت همان مانور گرفته شد.
- [ ] شماره سریال/تاریخ/ساعت روی پرینت خوانا است.
- [ ] پارامترها و دقت چاپ ثبت شد.
- [ ] PDF/عکس با نام `test_id` و `maneuver_key` ذخیره شد.
- [ ] نسخه کاغذی و فایل دیجیتال هر دو نگه داشته شد.

## ۵. نرم‌افزار رسمی MIR

- [ ] MIR Spiro یا winspiroPRO باز شد.
- [ ] همان مانور از دستگاه/حافظه Import شد.
- [ ] شماره سریال و زمان در نرم‌افزار با پرینت/نمایشگر تطبیق داده شد.
- [ ] خروجی PDF/Print همان مانور ذخیره شد.
- [ ] اگر Export CSV/Excel وجود دارد، فایل خام ذخیره شد.
- [ ] دقت و واحد هر ستون ثبت شد.
- [ ] نسخه نرم‌افزار و تنظیمات واحد ثبت شد.
- [ ] هیچ ویرایش/بهترین‌سازی/حذف مانور انجام نشد.

## ۶. بسته USB و SpiroLab

- [ ] لاگ کامل session ذخیره شد.
- [ ] `SDA`/شناسه دستگاه در لاگ موجود است.
- [ ] پاسخ شروع FVC (`0x08`) با نوع گام و مقدار ثبت شد.
- [ ] همه بسته‌های زنده با زمان، نوع، raw و hex ذخیره شدند.
- [ ] `cod_LAST` خام همان مانور ذخیره شد.
- [ ] `cod_CURVE` خام همان مانور ذخیره شد.
- [ ] طول و SHA-256 فایل‌ها ثبت شد.
- [ ] `association_evidence` نوشته شد: توالی capture، تکمیل طبیعی، تک‌خواندن، سریال.
- [ ] هیچ داده خام دستکاری/تریم/ویرایش نشد.
- [ ] در صورت امکان، یک capture تکراری کنترل‌شده برای آزمون stale ثبت شد.

## ۷. جدول جفت‌سازی

برای هر مانور یک ردیف:

| فیلد | مثال | الزامی |
|---|---|---|
| `test_id` | `LAB-2026-11-A` | بله |
| `maneuver_key` | `LAB-2026-11-A-M1` | بله |
| `sequence` | `1` | بله |
| `pre_post` | `PRE` | بله |
| `recorded_at` | `2026-11-02T10:15:00+03:30` | بله |
| device model | `Spirolab` | بله |
| firmware | `...` | بله |
| display/print present | yes/no | بله |
| MIR software present | yes/no | بله |
| USB capture present | yes/no | بله |
| SpiroLab value present | yes/no | بله |
| same-maneuver evidence | `capture token + print timestamp` | بله |
| operator initials | `AB` | اختیاری |
| notes | `...` | اختیاری |

قاعده: `test_id` تنها کافی نیست. اگر `maneuver_key`، ترتیب، زمان و شاهد اپراتور سازگار نباشند، وضعیت `identity_not_established` است.

## ۸. داده‌های رسمی برای CSV

برای هر پارامتر:

- [ ] `parameter` استاندارد
- [ ] `value` با دقت رسمی
- [ ] `unit`
- [ ] `source` (`mir_device_display`, `mir_device_print`, `mir_software`)
- [ ] `precision`
- [ ] `evidence` (نام فایل/صفحه/ردیف)
- [ ] `same_maneuver_attested=yes` فقط با شاهد واقعی

اگر دقت رسمی را نمی‌دانید، `precision` را خالی بگذارید؛ ابزار `tolerance_not_established` می‌دهد و عدد را به‌عنوان برابری تفسیر نمی‌کند.

## ۹. کنترل کیفیت بسته

- [ ] `FVC >= FEV1` (با احتیاط).
- [ ] `FEV1/FVC` با مقادیر جفت‌شده سازگار است.
- [ ] `PEF time <= FET` (اگر هر دو موجودند).
- [ ] واحدها هم‌بعدند.
- [ ] هیچ ردیف بدون منبع نیست.
- [ ] هیچ ردیف تکراری با منبع متفاوت بدون توضیح نیست.
- [ ] فایل‌ها با SHA-256 فهرست شده‌اند.
- [ ] هیچ فایل بیمار/هویتی در بسته نیست.
- [ ] هیچ credential/token در بسته نیست.
- [ ] اندازه بسته منطقی است (زیر ۵ MiB برای ورودی ابزار).

## ۱۰. بسته تحویل فاز ۲

```text
evidence/
  manifest.json
  pairing.csv
  device/
    display-<maneuver>.jpg
    print-<maneuver>.pdf
  mir-software/
    export-<maneuver>.pdf
    export-<maneuver>.csv
  usb/
    session-<test_id>.log
    last-<maneuver>.hex
    curve-<maneuver>.hex
  spirolab/
    values-<test_id>.csv
  checksums.txt
```

`manifest.json` حداقل شامل:

- `test_id`
- `data_origin: live_deidentified`
- دستگاه، firmware، سریال (در صورت نیاز)
- نسخه‌ها
- فهرست فایل‌ها + SHA-256
- `maneuver_key`ها
- شاهد جفت‌سازی
- محدودیت‌ها

## ۱۱. توقف‌های اجباری

اگر هر یک از این موارد رخ داد، مقایسه را متوقف کنید:

- فقط `test_id` مشترک است و شاهد مانور نیست.
- زمان/ترتیب مانورها با هم نمی‌خواند.
- فایل `.mir` به‌عنوان داده خام USB ارائه شده است.
- خروجی رسمی فقط یک عدد گردشده دارد و دقت آن معلوم نیست.
- دستگاه و نرم‌افزار هم‌زمان به USB دسترسی داشته‌اند.
- برای خواندن داده باید فرمان ناشناخته ارسال شود.
- فایل حاوی داده هویتی است.
- کالیبراسیون/BTPS/کیفیت مانور تأیید نشده و قرار است نتیجه بالینی گرفته شود.
