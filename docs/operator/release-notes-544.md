# SpiroLab 5.4.4 — یادداشت انتشار

این انتشار یک اصلاح محدود روی ۵.۴.۳ است. الگوریتم‌های اندازه‌گیری، فرمول‌های FVC/FEV1/PEF/FET/FEF25–75، فرمول `EVol`، انتخاب سه مانور، قواعد BEST VALUES، کیفیت JPEG ۷۰، ابعاد ۱۸۰۰×۲۵۴۶، چاپ A4، پروتکل USB/MIR، رمزگشایی `cod_LAST`، CSRF/نشست Firefox و سیاست ثبت HLine تغییر نکرده‌اند.

## اصلاح اصلی

در ۵.۴.۳ مقادیر FVC، FEV1، PEF و FEF25–75 برای گردش‌کار نسخهٔ ۴ فقط از حداکثر سه مانور انتخاب نهایی محاسبه می‌شدند، اما `VEXT` از تمام مانورهای واقعی فعال معاینه انتخاب می‌شد. از ۵.۴.۴:

- `VEXT` برای `SelectionWorkflowVersion >= 4` فقط از همان مجموعهٔ `ReportManeuverIds` (حداکثر سه مانور) محاسبه می‌شود.
- قاعدهٔ مقدار تغییر نکرده است: بیشترین `EVol` مثبت و کمتر از ۲۰۰ میلی‌لیتر (`0 < EVol < 200 mL`).
- انتخاب یک، دو یا سه مانور معتبر مجاز است؛ الزام دقیقاً سه مانور وجود ندارد.
- مانور انتخاب‌نشده، ردشده، حذف‌شده، شبیه‌سازی‌شده یا بازپخش‌شده در `VEXT` اثر ندارد.
- مقدار ناموجود، صفر، منفی، `NaN`/`Infinity` یا ۲۰۰ و بالاتر وارد محاسبه نمی‌شود.
- اگر در مجموعهٔ انتخاب‌شده هیچ `EVol` واجد شرایطی نباشد، `VEXT` به‌صورت `unavailable` با علت فارسی گزارش می‌شود؛ صفر، مقدار دستی پنهان یا مقدار پیش‌فرض ساخته نمی‌شود.

## یک منبع مشترک

`ClinicVext.SelectForExam(Exam)` تنها منبع محاسبهٔ `VEXT` برای بخش‌های زیر است:

- آماده‌سازی درخواست HLine در `SubmissionDraft`
- اعتبارسنجی منشأ در `DeviceProvenanceValidator`
- بخش `vextSelection` در JSON نسخهٔ ۲

برای `SelectionWorkflowVersion < 4` همین تابع به رفتار تاریخی `ClinicVext.Select(exam.Trials)` برمی‌گردد. بنابراین پرونده‌های گردش‌کار ۳، JSON تاریخی، XML قدیمی، journal و نتیجه‌های قبلی بدون مهاجرت اجباری یا بازنویسی باز می‌شوند.

## JSON

- `vextSelection.valueMl` و `vextSelection.sourceManeuverId` برای نسخهٔ ۴ از مجموعهٔ انتخاب‌شده می‌آیند.
- `vextSelection.scope` مقدار `selected_max_three_real_usb_live_maneuvers_only` و `rule` عبارت انتخاب از مانورهای نهایی را نشان می‌دهند.
- `spirometry.VEXT` همچنان نقش تاریخی/بازبینی دستی محلی خود را دارد و به‌عنوان نتیجهٔ نهایی HLine معرفی نمی‌شود.
- `siteExport` برای گردش‌کار ۴ همچنان بازنشسته است.
- `schemaVersion=2` و ساختار JSON حفظ شده و فیلد جدید غیرضروری اضافه نشده است.
- ردیف‌های `EVol` هر مانور در گزارش تصویری همچنان مقدار همان مانور را نشان می‌دهند.

## محدودیت‌ها

اعتبارسنجی سخت‌افزاری مستقل روی دستگاه واقعی، رایانهٔ کاملاً پاک، BTPS و ارسال تولیدی HLine برای بیماران واقعی همچنان **PENDING** است. این اصلاح فقط دامنهٔ انتخاب `VEXT` را هم‌راستا می‌کند و جای آزمون میدانی یا اعتبارسنجی بالینی را نمی‌گیرد.
